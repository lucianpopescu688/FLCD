================================================================================
  2. Architecture & Design of FA Integration
================================================================================

In Laboratory 3, lexical analysis relied on Flex-generated regular expression
matching. In Laboratory 4, formal Finite Automata (FA) and equivalent Regular
Grammars (RG) were constructed for the Cloud DSL's identifiers and constants.

In Laboratory 5, the scanner replaces regular expression pattern matching with
explicit, state-driven Finite Automata. When the scanner encounters candidate
lexemes:
  - It delegates identifier recognition to the Identifier FA (`fa_identifier`).
  - It delegates integer constant recognition to the Numeric FA (`fa_number`).
  - It delegates string literal recognition to the String FA (`fa_string`).

Each automaton:
  - Starts in its initial state `q0`.
  - Transitions through states character-by-character according to its transition
    function `delta`.
  - Determines acceptance based on whether scanning halts in an accepting
    (final) state `F`.
  - Returns the length of the longest recognized prefix.


================================================================================
  3. Formal Specifications of Finite Automata
================================================================================

3.1. Identifier Finite Automaton
--------------------------------------------------------------------------------
Recognizes valid identifiers according to the Cloud DSL specification:
must start with an ASCII letter, followed by any combination of letters,
digits, or underscores.

Formal Definition:
  M_id = (Q, Sigma, delta, q0, F)
  - Q = {q0, q1}
  - Sigma = {a-z, A-Z, 0-9, _}
  - q0 = q0 (initial state)
  - F = {q1} (accepting state)

Transition Function (delta):
  delta(q0, [a-zA-Z])       = q1
  delta(q1, [a-zA-Z0-9_])   = q1

Regular Grammar Equivalent (from Lab 4):
  G = ({S, A}, Sigma, P, S)
  P = {
    S -> letter A | letter,
    A -> letter A | digit A | underscore A | letter | digit | underscore
  }


3.2. Numeric Constant (Integer) Finite Automaton
--------------------------------------------------------------------------------
Recognizes valid integer constants:
  - Exactly "0", OR
  - Positive integer starting with a non-zero digit [1-9], OR
  - Negative integer starting with "-" followed by a non-zero digit [1-9].
Malformed numbers like -0, 007, or numbers with trailing letters are rejected.

Formal Definition:
  M_num = (Q, Sigma, delta, q0, F)
  - Q = {q0, q1, q2, q3}
  - Sigma = {'0', '1'-'9', '-'}
  - q0 = q0 (initial state)
  - F = {q1, q3} (accepting states)

Transition Function (delta):
  delta(q0, '0')     = q1    (Matches zero; q1 has no outgoing transitions)
  delta(q0, '-')     = q2    (Negative prefix; requires nonzero digit)
  delta(q0, [1-9])   = q3    (Positive integer start)
  delta(q2, [1-9])   = q3    (Negative integer start)
  delta(q3, [0-9])   = q3    (Subsequent digits)

Regular Grammar Equivalent (from Lab 4):
  G = ({S, A, B}, Sigma, P, S)
  P = {
    S -> '0',
    S -> '-' A,
    S -> [1-9] B | [1-9],
    A -> [1-9] B | [1-9],
    B -> [0-9] B | [0-9]
  }


3.3. String Constant Finite Automaton
--------------------------------------------------------------------------------
Recognizes double-quoted string literals containing allowed characters:
alphanumerics and standard punctuation (. : - _ , ! / @ # ? = & and space).

Formal Definition:
  M_str = (Q, Sigma, delta, q0, F)
  - Q = {q0, q1, q2}
  - Sigma = {'"', valid_char_set}
  - q0 = q0 (initial state)
  - F = {q2} (accepting state)

Transition Function (delta):
  delta(q0, '"')         = q1    (Opening quotation mark)
  delta(q1, valid_char)  = q1    (Characters inside string)
  delta(q1, '"')         = q2    (Closing quotation mark, accepting)


================================================================================
  4. Symbol Table (ST) and Program Internal Form (PIF)
================================================================================

4.1. Symbol Table (ST)
----------------------
- Data Structure: Hash Table with Open Addressing and Linear Probing.
- Capacity: m = 101 (prime number).
- Hash Function:
    h(k) = (sum of ASCII codes of symbol mod 101) + 1
- Collision Resolution:
    probe(i) = ((h(k) - 1 + i) mod 101) + 1  for i = 0, 1, 2, ...
- Identifiers and constants are inserted once; duplicates reuse the existing index.

4.2. Program Internal Form (PIF)
--------------------------------
- Reserved words, operators, separators: ST Index = 0.
- Identifiers: Token = "id", ST Index = 1..101.
- Constants:   Token = "const", ST Index = 1..101.


================================================================================
  5. Lexical Error Diagnostics
================================================================================

The scanner performs strict validation and diagnostics:
  1. Malformed identifiers or numbers (e.g. `123invalid_id`, `007`, `-0`):
     Detected when numeric FA accepts a prefix but trailing characters violate
     syntax, or when leading zero / negative zero is detected.
  2. Invalid characters in strings (e.g. `$` in `"Invalid$CharacterInString"`):
     String FA stops transitioning and halts in non-final state `q1`.
  3. Unclosed strings (e.g. `"This string never closes;\n`):
     String FA encounters end-of-line before reaching accepting state `q2`.
  4. Unrecognized single characters (e.g. `!`, `@`):
     Reported as unrecognized token errors.
